# 多平台构建指南（小游戏 / Steam / iOS / Google Play）

> 原则：**单 main 分支 + 平台 Bridge 抽象层 + CI 按目标注入宏**。平台差异不开分支、不双份维护热更代码。

## 平台矩阵

| | 微信小游戏 | Steam | iOS | Google Play |
|---|---|---|---|---|
| 构建目标 | WebGL → 官方转换工具二次转换 | StandaloneWindows64 | iOS（需 macOS） | Android |
| 平台宏 | `MINIGAME` | `STEAM` | —（UNITY_IOS） | —（UNITY_ANDROID） |
| 变现 | **仅广告（产品决策：不做内购）** | 内购（Steamworks 微交易） | 内购（Unity IAP） | 内购（Unity IAP）+ 广告 |
| 登录 | 微信 code → openid | Steam 票据 | Sign in with Apple | Play Games |
| 宏生效方式 | CIBuild 注入，编译期即排除支付路径 | 同左 | Unity 内建宏 | Unity 内建宏 |

所有目标统一附加 `OFFLINE_BUNDLE`（资源全内置的整包模式，适合首发/提审）；上线转 CDN 热更时去掉该宏并配置 `GameApp.RemoteHostURL`。构建结束后 CI 会**自动剥离本次注入的宏**（无论成败），ProjectSettings 还原到构建前状态，编辑器开发环境不受影响。

## 一键构建

```bash
# 本机（Git Bash）——默认打 win steam android webgl
Tools/ci/build_all.sh
# 指定目标
Tools/ci/build_all.sh steam android
# 覆盖 Unity 路径
UNITY_BIN=/path/to/Unity Tools/ci/build_all.sh

# 或直接调 Unity（CI 平台通用）
Unity -batchmode -quit -projectPath . -executeMethod CIBuild.BuildFromArgs -ciTarget steam
```

- 目标：`win / steam / android / webgl / ios / all`（`ios` 仅 macOS；`all` 打本机全部）
- 产物：`Build/<target>_<bundleVersion>-<gitHash>/`，日志 `Build/logs/ci_<target>.log`
- 流程（CIBuild.cs）：切平台+注宏 → HybridCLR 全量生成 → 拷热更/AOT dll → UI 契约校验 → YooAsset SBP(LZ4) → BuildPlayer
- UI prefab 是烘焙生成物：**改布局代码后手动跑 Build/UI/Bake UI Prefabs 并提交**（CI 不自动烘焙——Unity 每次烘焙的对象哈希都会变，自动烘焙会造成无意义 churn；CI 用契约校验拦截忘烘）
- 也可在编辑器菜单 **Build/CI/** 手动触发

### 各端发布注意

- **微信小游戏**：`webgl` 产物是底包，还需用微信官方「Unity 转换工具」二次转换（首包体积/性能约束是当前最大技术风险，先做可行性验证再定美术规格）；iOS 端小游戏无虚拟支付。
- **Android**：正式包需在 Player Settings 配置 keystore（CI 不代管密钥）。
- **iOS**：产出 Xcode 工程 → macOS Runner 上出 ipa → App Store Connect；国区上架需版号。
- **Steam**：`steam` 包 + Steamworks 后台配置 depot；支付走 Steam 微交易（需 AppID）。

## 平台 Bridge 层（Assets/HotUpdateScripts/Platform/）

与 AdBridge/ShareBridge 同款「接口 + SetProvider + 桩」模式：

- `LoginBridge`（ILoginProvider）：业务只调 `LoginBridge.LoginAsync()`。Guest 走现行 `/api/login`（行为不变）；平台身份走 `/api/auth/{platform}`。
- `PayBridge`（IPayProvider）：`IsAvailable` 决定付费入口显隐；`PurchaseAsync` 成功后拿 `PlatformReceipt` 交服务端验单。**MINIGAME 目标编译期固定 `UnavailablePayProvider("minigame-no-iap")`**。
- `PlatformBootstrap.Init()`（HotUpdateEntry 调用）：按宏选实现；未接 SDK 的桩 `IsAvailable=false` → 登录自动回退游客、付费入口隐藏。

### 接真实 SDK 的步骤（以 Steam 为例）

1. 引入 Steamworks.NET（AOT 侧程序集）；
2. `PlatformBootstrap.CreateLogin/CreatePay` 里把 `SteamLoginStub/SteamPayStub` 换成真实实现（接口不变）；
3. 服务端实现 `POST /api/auth/steam`（验票）与 `POST /api/pay/verify`（Steam 微交易验单后发货，流水入 `gold_tx`）；
4. 其余平台同理：iOS/Google 用 Unity IAP（receipt / purchaseToken 验单），微信用 code2session。

### 服务端待办（配合多端）

- `POST /api/auth/{platform}`：平台身份验签 → 绑定/创建 player → 发 Bearer token（客户端 `ApiClient.LoginWithIdentityAsync` 已就绪）。
- `POST /api/pay/verify`：验单 → 防重放（orderId + receipt 唯一约束）→ 发货 → 记流水。
- feature flags 增加 platform 维度（如 Steam 关广告位、小游戏关内购入口）。

### 坑位记录：DATA_CDN 为空 → bundle 全挂

- **现象**：YooAsset 版本/清单能拉到（普通 UnityWebRequest 路径），但首个 bundle 即报 `Unable to open archive file: http://…/xxx.bundle`。
- **根因**：WX SDK 的 WXAssetBundle 缓存层（`WXAssetBundle.jslib` 的 `url2path`/`isWXAssetBundle`）靠 `GameGlobal.unityNamespace.DATA_CDN` 前缀把远端 URL 映射成 `USER_DATA_PATH/__GAME_FILE_CACHE/` 本地路径。转换器在 `assetLoadType=1`（首包数据走包内分包）时**不回填 DATA_CDN**（game.js 里 `DATA_CDN: ''`）→ 映射串损坏 → C# 侧 `DownloadHandlerWXAssetBundle.get_assetBundle` 回退 `LoadFromFile(原始URL)` → 引擎报 unable to open archive。
- **修复**：`WXMinigameExport.PatchDataCdn()` 导出后补写 `DATA_CDN: '<WX_CDN 或默认 http://127.0.0.1/CDN>'`（与 `GameApp.RemoteHostURL` 同前缀；真机预览用 `WX_CDN=http://<局域网IP>/CDN` 覆盖）。幂等：SDK 已写正确值则跳过。
- **验证**：Network 面板 `DefaultPackage` 清单三件套 + `6eddf0bd…/045b…/d187…/a64b…` bundle 全部 200 (xhr)，Console 无 archive 错误，场景正常渲染。
- **遗留**：①UI 美术图缺 `icon_coin`/`btn_blue`（UITheme 降级警告，占位显示）；②netstandard AOT 补充元数据未收集（警告，非阻塞）；③包内 StreamingAssets 与 CDN 双份 bundle（约 2.2MB 冗余，后续做「首包资源在包内直读」方案时消化）。~~tbskill~~（已修：Luban 从未定义该表，加载列表误多写，aff7210 删除）。

### 坑位记录：热更 DLL 停留旧版 → 运行时行为"穿越"

- **现象**：源码已是协程化新版本，小游戏运行时却执行旧同步逻辑——`WebGL platform does not support synchronous loading` → `cfg.Tables..ctor` 里 NRE；且栈形状（`Tables..ctor` 直接被 `StartGame` 调）与源码（lambda 只查字典）对不上。
- **根因 1**：`WXMinigameExport` 只做 WebGL 构建+转换，不重建 YooAsset 资源包；协程化改造后直接导出，包内 `Game.HotUpdate.dll` 还是 12 小时前的旧货。**判别法：对照 `Assets/AssetRaw/HotUpdateDlls/*.bytes` 的 mtime 和运行日志里的程序集大小。**
- **根因 2**：`GameApp.EnterHotUpdate` 裸 `method.Invoke`——`StartGame` 改返回 IEnumerator 后，Invoke 只创建枚举器不执行代码体（迭代器惰性），新 DLL 下会**静默无动作**。已补 `StartCoroutine` 驱动（兼容旧 void 入口）。
- **修复**：新增 `CIBuild.BuildMinigameBundles`（菜单 Build/CI + 批处理入口，只重建资源包不 BuildPlayer）+ `EnterHotUpdate` 协程驱动。
- **验证**（0.1.0-a56dc97）：`热更代码执行中！` → 14 表加载（13 成功 + tbskill 缺资产跳过）→ `配置加载完成：道具 4 条，宝箱 6 档，角色 9 个` → `PlatformBootstrap 平台=Guest` → `[UIManager] Show LoginScreen`，此后零异常。

### 坑位记录：热更代码引用被裁剪的 BCL 类型 = 加载期炸弹（2026-11-08 全链路收官战）

登录链路三连坑，全部与 WASM/HybridCLR 特性相关：

1. **HttpClient 在 WASM 上不存在**——`System.Net sockets` 无实现，`await` 永不完成、按钮置灰无反馈。修复：ApiClient WebGL 分支走 `UnityWebRequest`（WX SDK XHR 补丁通道，与 YooAsset 同路），单机/编辑器保留 HttpClient。
2. **`await Task.Yield()` → 热更程序集加载即崩**——async 状态机产生 `YieldAwaiter` 字段，运行 wasm 的裁剪版 mscorlib 没有该类型 → `Assembly.Load` 时 `ExecutionEngineException: ReadTypeFromResolutionScope TYPEREF fail` → 热更整体加载失败、模拟器卡死。Cecil 核对裁剪库：`TaskCompletionSource`/`DelayPromise` 同样被裁——**Task 生态在纯热更侧没有可用的"等一帧"原语**。
3. **修复：接入 UniTask 2.5.11**（嵌入式包 `Packages/com.cysharp.unitask`）——`await req.SendWebRequest()` 走 UniTask 的 awaiter 扩展。两个必要配套：asmdef `autoReferenced: true`（Assembly-CSharp/AOT 引用 → 进 wasm）+ `Assets/link.xml` 整包保留（AOT 无静态引用点会被裁剪，热更引用被裁类型即上述 TYPEREF 崩）。

**通用规律：热更代码每引用一个 AOT 没用过的类型（尤其 BCL 冷门类型），都是一个潜在的 Assembly.Load 期炸弹。** 新增第三方库给热更用时，必须：进 AOT（被 Assembly-CSharp 引用）+ link.xml 整包保留。

### 键盘（WXKeyboard.Bind）

WASM 无键盘事件，且 SDK（DisableKeyboardInput.cs）主动关了 `WebGLInput.mobileKeyboardSupport`——InputField 两条输入路径全断。`WXKeyboard.Bind(input)`：Select 弹 `wx.showKeyboard`（回填文本/字数上限）→ OnKeyboardInput 回填 text → Confirm/失焦收起。仅 UNITY_WEBGL 编译。

### 迭代速度经验

- **纯热更侧改动**（业务/UI/配置代码）：`BuildMinigameBundles` → 切 junction → 开发者工具点编译即可，**无需重新导出**（wasm 不含热更代码，运行时全从 CDN 拉）——分钟级。
- **AOT 侧改动**（GameApp/SDK/新程序集/宏）：必须重跑 `WXMinigameExport.Run`。

## 分支与发布策略

- **main 唯一长期分支**；提审冻结期用短命 `release/*` 分支 cherry-pick 修复，发完即删。
- 热更代码（HybridCLR）与资源（YooAsset）全平台共享，平台差异只允许出现在 `Platform/` 与编译宏内。
- 双周运营活动经热更下发（Android/iOS 免发版），不受各商店审核节奏牵制。
